# AI 파트 구현·검증 기록

2026-11-09. 현재 독립적으로 구현 가능한 AI 로직을 개발하고 실제 OpenAI API 및 로컬·Docker 환경에서 검증했다. Spring 프로젝트에 통합됐다는 의미는 아니다.

| IT 판별 | 기존 검증 프롬프트·독립 JSON Schema, 메타데이터 호출, NOT_IT 거절·UNSURE 사용자 확인 정책 함수 |
| 영상 분석 | 기존 확정 모델·프롬프트·스키마 호출, 입력 토큰 예산, 최대 3회 출력 복구, 실제 토큰·시간·시도 기록 |

## 실행 검증

| 항목 | 결과 | 근거 파일 |
|---|---|---|
| 로컬 코드 테스트 | 34/34 통과 | test_ai_runtime.py, test_chat_stream.py, test_yousum_chat.py |
| Docker 오프라인 테스트 | 네트워크·키 없이 34/34 통과 | yousum-ai-tools:dev, `docker run --rm --network none` |
| Compose | 실행·결과 볼륨 쓰기 확인, 실제 .env·samples·.venv 이미지 제외 확인 | compose.yaml, results/docker-write-check.txt |
| 기존 분석 selftest | 통과 | yousum_ai.py selftest |
| 실제 채팅 스트리밍 | 12/12, 모든 delta와 최종 content 일치 | results/chat-stream/summary.json |
| 채팅 응답 시간 | 중앙값 1.478초, 첫 본문 중앙값 1.271초 | results/chat-stream/*.json |
| IT 판별 | IT→ANALYZE, NOT_IT→REJECT, UNSURE→CONFIRM_REQUIRED | results/gate-*.json |
| 실제 42.2분 영상 분석 | 1회 성공, 38.1초, 구간 8개, 마지막 시각 2,533,000ms | results/analysis42-final.json |
| 60분 합성 입력 | 1회 성공, 32.99초, 구간 9개, 마지막 시각 3,600,000ms | results/synthetic60.json |

모델은 모두 `gpt-6-luna`, effort `low`다. API 키는 기존 로컬 .env에서 읽었다. API 호출량·시간은 결과 JSON의 usage·meta에 보관한다. 새 실행의 모델 호출은 채팅 12회, 판별 3회, 분석 5회(초기 42분 3회 + 수정 후 42분 1회 + 합성 60분 1회), 총 20회다. 입력 검증에서 거절된 두 시도는 API를 호출하지 않았다.

채팅 케이스 구성은 직접 만든 가상 근거 9건 + 기존 실제 영상 자막에서 수동 선택한 근거 3건이다. 실제 자막 시험은 리팩토링 방법·마트 비유·35%/49%/67% 수치 보존을 확인했다. 이는 실제 검색 성능 평가가 아니다. 자동 기대값과 답변을 읽어 확인했지만 독립적인 사람의 전체 품질 검토를 대체하지 않는다.

합성 60분은 기존 7.5분 자막을 반복하고 시각을 이동한 부하 입력이다. 실제 60분 영상의 내용 전개·사실 정확도·구간 품질을 검증한 결과로 해석하지 않는다.

## 시험 중 발견하고 수정한 것

1. 기존 자막은 마지막 endMs가 영상 길이를 조금 넘었다. 정규화 단계에서 영상 끝으로 자르고 보정 건수를 남긴다. 정규화 후 시간 범위 검사는 계속 엄격하게 적용한다.
2. 42분 결과의 상세 팁이 앞 구간 자막과 현재 구간 자막을 함께 인용했다. 초기 강화 검사가 이를 오류로 거절해 3회가 종료됐다. 명세와 대조한 뒤 상세의 유효한 교차 구간 참조는 보존하고 경고로 처리했다. 대표 근거는 해당 구간 안이어야 하며, 어느 필드에서도 없는 자막 ID는 허용하지 않는다. 초기 거절 기록은 results/analysis42.json에 보존했다.
3. 스트리밍 중간에 JSON escape·이모지가 잘려도 본문에 JSON 조각이 섞이지 않도록 문자 단위 시험을 추가했다. EOF·거절·출력 한도·출처 검증 실패는 정상 완료로 처리하지 않는다.

42분 최종 결과에는 상세의 교차 구간 참조 경고 2개가 남았다. 원래 출처 ID를 임의로 바꾸거나 삭제하지 않았다.

## 백엔드에서 연결할 순서

1. 판별 결과에 gate_action과 같은 정책을 적용하고, UNSURE의 사용자 확인 상태를 서버에서 유지한다.
2. 업로드 자막의 소유권·객체 버전 검증 후 입력 정규화·모델 호출·결과 검증 규칙을 Worker에 연결한다.
3. 모델 sectionKey를 실제 Section PK로 매핑한다. 자막 시간은 서버 원본 데이터에서 계산한다.
4. Chat에서 허용된 검색 근거를 AI 입력으로 전달하고, content delta를 SSE에 연결한다.
5. 생성 종료 후 현재 권한·삭제 여부·출처를 재검사하고, 대화 저장 성공 뒤 SSE done을 발행한다.

## 남은 외부 의존 작업

- 실제 Spring AI·Worker·Chat·DB·모바일의 통합 실행. 이 워크스페이스에는 Spring 프로젝트가 없다.
- 실제 60분 영상 샘플과 더 넓은 사용자 질문으로 품질 확인.
- 운영 시간 제한·제품 질문 한도·이용량 정책의 최종 적용. 로컬 token·문자 제한은 실행 예산이다.
- 추천 영상 기능은 사용자가 나중에 결정하기로 한 범위다.

임베딩·벡터 DB·검색 구현은 백엔드 A 담당이다. AI 파트 전달물은 현재 검증한 모델·프롬프트·스키마·입출력 및 오류 처리 규칙이다.
