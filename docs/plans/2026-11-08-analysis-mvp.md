# 영상 분석 작업 처리 MVP

## 범위

- 이슈 #4의 배치 생성·분석 접수·작업/배치 조회·수집 실패 보고·수동 재시도를 구현한다.
- API와 Worker는 별도 Spring MVC 앱, PostgreSQL/pgvector는 로컬 Docker, 자막은 실제 GCS 객체 참조를 사용한다.
- 업로드 URL 발급·영상 가져오기·보관함·검색·채팅 API는 다른 기능의 범위다. 공유 영상·업로드·완료 기록의 DB 연결 형식은 문서와 테스트로 제공한다.
- 로그인·결제·이용 한도·Cloud Tasks·FCM은 제외한다. 로컬 시연 사용자 ID는 서버 설정으로 고정하며 요청 헤더의 임의 사용자 ID를 신뢰하지 않는다.
- 기존 미커밋 `.agents/rules/api.md`, `.github/pull_request_template.md`는 수정하거나 커밋하지 않는다.

## 작은 커밋의 진행 순서

1. 커밋 리뷰 지침·구현 계획 등록.
2. Java 21 API·Worker·공통 라이브러리의 독립 빌드 구성.
3. 로컬 PostgreSQL/pgvector·Flyway·공통 응답/예외 기반.
4. 분석 배치·작업·업로드 참조·결과/기록 모델과 상태 전환.
5. 배치 생성·조회·수집 실패 보고 API와 멱등성.
6. GCS 객체 검증·분석 접수·상태 조회·수동 재시도.
7. Worker 선점·만료 복구·자막 검증·자동 재시도.
8. AI 응답 검증·결과/검색 데이터 저장·완료 확정.
9. 실제 PostgreSQL과 HTTP 경계의 통합 시나리오, 실행/AI 연동 안내, 최종 리뷰.
10. dev 대상 PR 생성 후 API 흐름 HTML에 실제 함수·커밋·PR 링크 반영.

각 구현 단위는 필요한 테스트를 먼저 작성해 실패를 확인하고 구현한다. 빌드 설정 변경은 독립 JAR 빌드로 확인한다. 커밋 후 별도 에이전트가 `.agents/reviewers/commit-reviewer.md`에 따라 읽기 전용으로 검토하며, 차단 문제가 해결되어야 다음 단위로 넘어간다.

## 핵심 동작·검증

- 같은 사용자·videoId의 진행 작업/완료 결과를 재사용한다. 동일 멱등 키의 다른 본문은 409, 중복 등록은 DB 제약·잠금으로 차단한다.
- uploadId의 사용자·영상·배치 항목·GCS generation을 연결한다. 실제 자막 크기·한국어·시간 범위·최대 60분을 다시 검증한다.
- 짧은 DB 트랜잭션으로 작업을 선점하고 외부 요청 중에는 잠금을 유지하지 않는다. lease/runToken으로 재시작 복구와 오래된 실행의 저장을 제어한다.
- 자동 실행은 최초 포함 최대 3회다. 최종 실패/재시도 가능 여부를 구분하며 수동 재시도는 새 배치·작업과 previousJobId로 연결한다.
- 결과·구간 ID를 확정한 뒤 검색 데이터를 연결한다. 결과·검색 데이터·개인 기록이 준비되어야 COMPLETED를 반환한다.
- 테스트는 정상·동시 중복·다른 사용자/항목·잘못된 자막·AI 실패·lease 만료·수동 재시도·부분 배치 실패를 포함한다.

## 외부 연동의 확인 범위

GCS 인증과 실제 분석 AI의 주소·요청/응답 규격은 현재 확인되지 않았다. 비밀값은 요청하거나 Git에 저장하지 않는다. 실제 GCS 클라이언트와 설정 가능한 AI HTTP 연동을 구현하고, 테스트에서는 외부 경계만 대체한다. AI 계약은 팀의 실제 명세가 확인되면 맞추며, 테스트 서버 응답을 실제 AI 분석으로 표시하지 않는다. 외부 실연동에 필요한 설정이 없으면 그 검증은 미확인으로 PR에 남긴다.
